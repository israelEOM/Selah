# Offline Reading Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A member can open the app with no connection and still see Today, their church's studies (every published one, opened before or not), and upcoming events, with a quiet note that they're seeing a saved copy.

**Architecture:** Progress ticks already live in `SharedPreferences` (`lib/src/data/progress.dart`), so only server reads need work. `SelahRepository` gains a read-through cache. Each member-facing read stores the raw JSON rows it got under a `cache:` key. When a read fails with a network error, the repository parses the stored rows instead, so the models' `fromJson` stays the single parser. A shared `OfflineStatus` (a `ChangeNotifier`) records whether the last read reached the server, and the shell shows a one-line note while it's offline. While online, the shell saves every published study of the current church once per app run so studies that were never opened also work offline.

**Tech Stack:** Flutter, Riverpod 3, supabase_flutter 2.18, shared_preferences, package:http (`ClientException`, `MockClient` for tests).

**Spec:** None written. The requirements come from the user's answers in the planning session, recorded under Global Constraints.

## Global Constraints

- Offline scope: member reads only: Today, church page, study and reader pages, events, church picker. Admin pages and every write (join, accept invite, admin edits) still need a connection and keep their current errors.
- All published studies of the current church are saved for offline use while online, not only ones already viewed.
- Offline note copy (key `offlineNote`): es "Sin conexión. Estás viendo tu copia guardada." · en "Offline. Showing your saved copy." · pt "Sem conexão. Você está vendo sua cópia salva." The template ARB is `app_es.arb`.
- The note shows only while the app is showing saved data, and disappears after the next read that reaches the server.
- "Offline" means a network failure (`http.ClientException`, which also covers socket errors on iOS/Android, or `TimeoutException`). A server answer (any `PostgrestException`, auth error) is never offline and never falls back to the cache.
- Read timeout: 10 seconds.
- Storage: `SharedPreferences`, keys prefixed `cache:`. No new storage package.
- Sign-out deletes every `cache:` key. Progress (`progress:`), chosen church and settings keys stay.
- Web: no service worker. On the web, saved data is used only while the page is already loaded. Offline launch is a native-app feature.
- Sermon thumbnails (`Image.network`) are not saved. Their existing `errorBuilder` fallback is enough.

## Review Focus

1. **Signed-in launch with no connection and an expired access token.** The person should stay signed in and land on Today with saved data. `Supabase.initialize` and `userIdProvider` must not sign them out. Covered by Task 5's device check.
2. **Sign out, then someone else signs in on the same device.** The first person's churches and roles must not appear. Pinned by `signOut clears saved reads` in Task 2.
3. **Server refusals.** A server error such as RLS or a 500 is not "offline". The person sees the error, not stale data. Pinned by `server errors do not fall back` in Task 1.
4. **A study unpublished after it was saved.** A null result from the server removes the saved copy, so it can't come back offline. Pinned by `null result removes saved copy` in Task 2.
5. **Saved events that have since ended.** The offline fallback hides events whose `ends_at` has passed, the same as the server query. Pinned by `offline events drop ended ones` in Task 2.

### Task 1: Offline primitives

**Files:**
- Create: `app/lib/src/data/offline.dart`
- Modify: `app/pubspec.yaml`: add `http: ^1.6.0` under `dependencies`, since it is now imported directly.
- Test: `app/test/offline_test.dart`

**Interfaces:**
- Produces:
  - `class OfflineStore { Future<Object?> read(String key); Future<void> write(String key, Object? json); Future<bool> has(String key); Future<void> clear(); }`. Each method takes a key without the `cache:` prefix and adds it itself. `write(key, null)` removes the key. `read` returns null when the key is missing or its JSON doesn't decode. `clear` removes every `cache:` key and nothing else.
  - `class OfflineStatus extends ChangeNotifier { bool get offline; void reached(); void fellBack(); }`. Each method notifies only when the value changes.
  - `bool isOfflineError(Object e)`. True for `http.ClientException` and `TimeoutException`.
  - `Future<Object?> readThrough({required OfflineStore store, required OfflineStatus status, required String key, required Future<Object?> Function() fetch, Duration timeout = const Duration(seconds: 10)})`. On success it writes the result, calls `status.reached()` and returns the result. On an offline error with a saved copy it calls `status.fellBack()` and returns the copy. Otherwise it rethrows.

- [ ] **Step 1: Write the failing tests** in `test/offline_test.dart`, with `setUp(() => SharedPreferences.setMockInitialValues({}))`:
  - `store round-trips json`: `write('a', [{'x': 1}])`, then `read('a')` equals `[{'x': 1}]`, and `has('a')` is true.
  - `corrupt saved json reads as missing`: seed prefs with `{'cache:a': '{not json'}`, then `read('a')` is null.
  - `clear keeps progress`: seed `cache:a`, `progress:s1` and `church`. After `clear()`, only `progress:s1` and `church` remain.
  - `fetch success saves and marks online`: start with `status.fellBack()`. `readThrough` with fetch returning `[1]` returns `[1]`, `store.read(key)` gives `[1]`, and `status.offline` is false.
  - `offline error falls back`: with `[1]` saved, fetch throws `http.ClientException('x')`. The result is `[1]` and `status.offline` is true.
  - `timeout falls back`: fetch is `Completer().future`, `timeout: Duration(milliseconds: 10)`. The result is the saved copy.
  - `offline with nothing saved rethrows`: `expectLater(..., throwsA(isA<http.ClientException>()))`, and `status.offline` stays false.
  - `server errors do not fall back`: with a copy saved, fetch throws `PostgrestException(message: 'denied', code: '42501')`. It rethrows, and the copy is still there.
  - `status notifies only on change`: two `fellBack()` calls fire one listener notification.

### Task 2: Repository reads fall back to saved copies

**Files:**
- Modify: `app/lib/src/data/repository.dart` (constructor, the reads listed below, `signOut`)
- Modify: `app/lib/src/data/providers.dart`: add `offlineStatusProvider`
- Modify: `app/lib/main.dart`: create one `OfflineStatus` and pass it to the repository and the override
- Test: `app/test/repository_offline_test.dart`

**Interfaces:**
- Consumes: `OfflineStore`, `OfflineStatus`, `readThrough` from Task 1.
- Produces:
  - `SelahRepository(SupabaseClient client, {OfflineStore? store, OfflineStatus? status})`. Defaults are `OfflineStore()` and `OfflineStatus()`, so existing callers compile unchanged.
  - `final offlineStatusProvider = Provider<OfflineStatus>((_) => OfflineStatus());` in `providers.dart`. `main` overrides it with the same instance it gives the repository.

Route these reads through `readThrough`. Each fetch returns the raw rows, and parsing stays where it is today:

| Method | Cache key |
|---|---|
| `publishedStudies(churchId)` | `studies:$churchId` |
| `studyBySlug(churchId, slug)` | `study:$churchId:$slug` |
| `churchBySlug(slug)` | `church:$slug` |
| `myChurches()` | `my-churches:$userId` |
| `publicChurches()` | `public-churches` |
| `roleIn(churchId)` | `role:$userId:$churchId` |
| `isPlatformAdmin(userId)` | `platform-admin:$userId` |
| `upcomingEvents(churchId)` | `events:$churchId` |

For `upcomingEvents`, the offline path also drops rows whose `ends_at` is not after `DateTime.now()`. Do that in the parse step, so it applies to both paths harmlessly. `signOut()` calls `_store.clear()` after `_client.auth.signOut()`, and also when sign-out throws.

### Task 3: Save every church study for offline

**Files:**
- Modify: `app/lib/src/data/repository.dart`: add `saveStudiesForOffline`
- Modify: `app/lib/src/app/shell.dart` (`_SelahShellState`)
- Test: `app/test/repository_offline_test.dart` (extend), `app/test/shell_test.dart` (extend)

**Interfaces:**
- Consumes: `publishedStudies`, `studyBySlug` and the store from Task 2.
- Produces: `Future<void> saveStudiesForOffline(String churchId)` on `SelahRepository`. It loads `publishedStudies(churchId)`, then calls `studyBySlug` one at a time for each card whose `study:$churchId:$slug` key is missing. It returns early without throwing when `_status.offline` is true, and it never throws to its caller.

In the shell, `ref.listen(currentChurchProvider, ...)` in `build` fires `ref.read(repositoryProvider).saveStudiesForOffline(church.id)` without awaiting. It runs at most once per church id per shell lifetime, tracked in a `Set<String>` on the state, and the call is wrapped in `try/catch` so a fake's `NoSuchMethodError` is ignored.
